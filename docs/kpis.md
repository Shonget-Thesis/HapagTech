# Key Performance Indicators (KPIs)

This document defines the Key Performance Indicators (KPIs) used to measure the performance, quality, and reliability of the HapagTech Smart Restaurant Ordering System. Each KPI includes a clear definition, measurement approach, and purpose to ensure consistent evaluation throughout development and testing.

---

## 1. Defect Rate

**Definition:**  
The number of defects identified within a specific development cycle (e.g., sprint or release).

**Measurement:**  
Total number of confirmed defects logged in the defect tracking system per sprint.

**Purpose:**  
Used to assess software quality and the effectiveness of testing practices. A high defect rate may indicate gaps in development or insufficient test coverage.

---

## 2. Lead Time

**Definition:**  
The total time taken for a task or feature to move from initial development to completion.

**Measurement:**  
Measured in days from the start of development (task assignment) to completion (merged and deployed).

**Purpose:**  
Evaluates development efficiency and workflow performance. Shorter lead times indicate a more optimized and responsive development process.

---

## 3. Deployment Frequency

**Definition:**  
The number of times the system is deployed or updated within a given time period.

**Measurement:**  
Count of successful deployments to the main branch or production environment per week.

**Purpose:**  
Indicates the team’s ability to deliver updates continuously. Higher deployment frequency reflects better CI/CD practices and faster delivery cycles.

---

## 4. Response Time

**Definition:**  
The time taken by the system to respond to a user request.

**Measurement:**  
Measured in milliseconds (ms), typically from request initiation to response completion.

**Purpose:**  
Evaluates system performance and user experience. Lower response times indicate a faster and more efficient system.

---

## 5. System Availability

**Definition:**  
The percentage of time the system remains operational and accessible to users.

**Measurement:**  
Calculated as:  
(System Uptime / Total Time) × 100

**Purpose:**  
Measures system reliability and stability. High availability is critical for ensuring continuous service to users.
